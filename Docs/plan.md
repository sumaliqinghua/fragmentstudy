# FragmentArticle 产品与实施规划

## 1. 核心目标

FragmentArticle 的目标不是要求用户完整掌握一份资料，而是把开始学习的阻力降到足够低，让用户愿意在碎片时间里多接触几个知识片段。

北极星指标：每周人均有效接触天数。

辅助指标：

- 导入成功率与导入到首个片段的耗时
- 首次学习启动率
- D1、D7 资料回访率
- 每周接触片段数
- 群聊和 Galgame 使用率
- 模式切换后的继续率

## 2. 产品边界

- 保留首页蛇形学习路径、新建、阅读、个人中心四个主 Tab。
- 首页一次只展示一份资料，不自动混合多个资料的内容。
- 科目只负责组织资料，不生成跨资料学习路径。
- 卡片、群聊和 Galgame 是同一资料的不同表现方式。
- “看过”不等于“掌握”，测验和奖励不阻塞后续内容。
- AI 生成内容需要能够返回原始 PDF 页码或网页来源。

## 3. 信息结构

```text
Subject 科目
  -> Article/Material 资料
    -> Knowledge Unit 知识片段
      -> Card / Dialogue / Galgame 表现形式
```

资料具有一个主科目，可以有多个标签。跨学科资料通过标签表达，不在第一版引入多主科目。

学习进度分为：

- 资料的卡片接触进度
- 群聊模式游标
- Galgame 模式游标
- 原文阅读位置

不同模式不再互相覆盖进度。

## 5. 技术实现

前端：React、TypeScript、Vite、Tailwind。

导入：

- PDF.js 负责文本层和页面渲染
- Tesseract.js 只处理疑似扫描页面
- Supabase Edge Function 使用 Readability 提取网页正文
- 主正文服务不可用时回退到只读正文服务

数据：

- `subjects` 保存用户科目
- `articles.subject_id` 关联主科目
- `articles.source_type/source_url` 保存来源
- `learning_progress.mode` 区分卡片、群聊和 Galgame
- 访客模式使用相同语义的本地存储结构
